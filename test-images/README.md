# 测试图片

`synthetic/` 的 10 张 PNG 是程序画出的圆角色块，模拟独立物品的轮廓。
不是工厂照片，不用于声称真实准确率，也不是模型训练集。
人工真实数量记录在 `labels.txt`；可用 `java tools/GenerateFixtures.java` 重新生成。

| 分类 | 图片 | 检查 |
| --- | --- | --- |
| 支持范围，6 张 | empty-0、single-1、uniform-7、uneven-7、shifted-7、noise-7 | 数量正确；改变间距仍为 7；小噪点不多算 |
| 异常提示，2 张 | clipped-2、dark-background | 分别出现贴边和大面积暗区警告，不能以数量正确作为通过条件 |
| 已知局限，2 张 | touching-2、low-contrast-3 | 展示错误；报告真实数量与估计数量，不算作准确通过 |

`uneven-7.png` 七个物品的顶边位置为 38、91、202、257、395、485、664，物品高度为 36 像素。
相邻空白为 17、75、19、102、54、143 像素，明确不等距。

## 真实照片怎么准备

先选同一种盖子，拍 10 张，全部人工数清并记录：

- 6 张互不接触、间距明显不同、背景干净的照片，覆盖少量 / 中量 / 较多物品。
- 2 张较难但仍在支持范围的照片，例如轻微倾斜或不同光照。
- 2 张真实常见的接触、套叠或透明反光照片，作为范围外挑战集，不混入首版达标率。

每张记录：文件名、人工总数、每个物品中心点（或编号标记图）、光照、是否接触、是否符合首版范围。
原图与标注图分开保存，算法输入原图。人工至少数两遍，数量不一致先解决标注差异。
若现场根本无法获得分离轮廓，就直接记录这个事实，调整算法范围，不改变真实摆放方式来宣称成功。

本仓库公开。现场原图默认放在被 Git 忽略的 `real/`；先检查是否包含人员、单据、客户信息。
仅经确认适合公开的脱敏样例，才另行加入仓库。不要把实拍图误放入合成图目录。
