# 第一版算法：逐个找独立轮廓

## 输入与输出

- 输入：方向正确、长边不超过 960 像素的 ARGB 像素数组。Android 在解码时缩小图片并处理 EXIF 方向。
- 输出：`Result.boxes`（按从上到下、同高度从左到右排序）、`count()`、`warnings`。
- 坐标：缩小后的图片，左右上下边界均包含该像素；结果图直接在同一张图片上画框，不映射回原图。
- 返回的是估计数量，没有经过校准的置信度分数。空警告列表不意味着计数正确。

## 处理流程

1. 透明像素先按白底合成，计算每个像素的亮度。
2. 亮度低于 **190 / 255** 视为前景。
3. 用八邻域连通区域搜索，把相连前景像素归为一个区域。
4. 忽略面积小于 `max(12, ceil(图片面积 × 0.0008))` 像素的区域。
5. 每个剩余区域给一个框和编号；区域数量就是估计数量。
6. 区域贴边时提示 `CLIPPED_OBJECT`；单一区域大于图片面积 45% 时提示 `LARGE_REGION`。

各物品之间的空白可以长短不同。算法不根据空隙数或平均间距推算数量。
没有使用把间隙填起来的形态学操作；缩小后仍需有清晰的背景间隔。
工作量及临时内存随像素数线性增长，图片大小在入口限制，Android 放到后台线程执行。

## 适用照片

首轮试验请使用同一种明显深于背景、表面较完整的物品，单列放在浅色无花纹背景上，
保留四周留白、避免硬阴影，拍完整；物品互不接触，间隔不限。
让物品占据画面足够面积：过小物品会被面积过滤忽略。
面积及亮度阈值是待实拍校准的初始值，不是通用盖子参数。

## 已知失败与检查方法

| 情况 | 可能结果 | 首版处理 |
| --- | --- | --- |
| 两个盖子紧贴、套叠、重叠 | 连为一个区域，少算 | 明确不支持；编号图人工检查；无法保证自动识别这种错误 |
| 透明、浅色、强反光 | 漏检或把一个物品拆成多个 | 重拍并留样，后续决定算法；零检测不等于现场没有物品 |
| 黑色背景或大阴影 | 背景被算作物品 | 大区域提示重拍，但并非所有阴影都能被检测 |
| 物品截断 | 不完整区域被计数 | 贴边警告，不能作为准确结果验收 |
| 背景文字、杂物 | 多算 | 使用纯背景，拍前裁去无关物品 |
| 物品小 / 间隙只有几像素 | 缩图后漏检 / 粘连 | 靠近拍摄、提高对比，重新验证 |

`touching-2.png` 实际为 2 个，基线通常给 1；`low-contrast-3.png` 实际为 3 个，基线给 0。
回归脚本将其报告为 `LIMITATION`，不把错误答案当作“准确通过”。
电脑图片读取使用 JDK ImageIO，Android 使用 ImageDecoder；缩图插值可能不同，
因此共用算法测试通过后仍要做真机照片验收。

## 何时换算法

先看真实错误图，不先训练模型。如果实物通常保持分离，优先验证光照、阈值和裁剪；
如果必须数套叠的一列盖子，先标出每个可见盖子的中心或分界线，
比较局部边缘/峰值方案与小型目标检测模型。任何新方案仍必须以逐个目标为依据，不要求等距。
